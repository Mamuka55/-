# EPIC AI — инструкция запуска

Для Windows 10/11, PowerShell. Путь к проекту дальше предполагается
`C:\Users\zendr\Desktop\ep\epic-ai` — при необходимости замените на свой.

Время до первого запуска: **10–15 минут** (основное — установка Electron, ~190 МБ).

---

## Что должно получиться

Два процесса:

| Процесс | Порт / признак | Зачем |
|---|---|---|
| **Backend** | `http://127.0.0.1:8787` | Авторизация, база знаний, RAG, AI, админка. Без него приложение не пустит никого |
| **Epic AI (Electron)** | иконка в системном трее, окна нет в панели задач | Splash → окно входа → панель 900×56 поверх игры |

Их можно запускать **одной командой** (вариант B ниже) или **раздельно** (вариант A) —
раздельно удобнее для отладки, потому что логи backend'а видны в своём окне.

```powershell
node -v      # нужно 20.11 или выше
npm -v
```

Если Node.js нет — поставьте LTS с <https://nodejs.org>.

## Шаг 1. Установить зависимости

Три установки, по одной на каждую часть проекта:

```powershell
cd C:\Users\zendr\Desktop\ep\epic-ai

npm install                  # корень: jsdom (для тестов)
cd backend
npm install                  # backend: fastify, cheerio, better-sqlite3 …
cd ..\electron
npm install                  # Electron (~190 МБ, самая долгая установка)
cd ..
```

**Проверка.** `better-sqlite3` должен встать готовым бинарником:

```powershell
cd backend
node -e "require('better-sqlite3'); console.log('better-sqlite3 OK')"
cd ..
```

Если команда напечатала `better-sqlite3 OK` — всё хорошо.
Если упала — ничего страшного: слой БД автоматически переключится на `sql.js`
(WASM, ноль нативных зависимостей), но тогда **нельзя одновременно** держать
запущенным сервер и выполнять CLI-команды (`db:migrate`, `sync`, `bootstrap`),
потому что `sql.js` держит базу в памяти процесса.

## Шаг 2. Создать и заполнить `.env`

```powershell
cd backend
copy .env.example .env
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Последняя команда напечатает строку — это значение для `SESSION_SECRET`.
Откройте `.env`:

```powershell
notepad .env
```

**Обязательно заполнить строки:**

GigaChat (Сбер, РФ): developers.sber.ru → GigaChat → получить ключ (личный
токен физлица; бесплатные пакеты токенов). Вставьте токен в `AI_API_KEY`.
TLS уже настроен из коробки: бандл НУЦ Минцифры (Root + Sub CA) лежит в
`backend/certs/russian_trusted_root_ca.pem` и подставлен в `AI_CA_CERT`
по умолчанию (подробности и порядок обновления — в `backend/certs/README.md`).

```ini
SESSION_SECRET=<вставьте строку из команды выше>

AI_PROVIDER=gigachat
AI_API_KEY=<личный токен GigaChat>
AI_MODEL=GigaChat-Pro
AI_MODEL_FALLBACK=GigaChat-Lite,GigaChat-Max
AI_CA_CERT=./certs/russian_trusted_root_ca.pem
```

Ключ Groq (бесплатный): <https://console.groq.com> → **API Keys** → Create API Key.
Формат ключа — `gsk_…`. Без ключа приложение работает, но на любой вопрос ответит
«AI-сервис временно недоступен» (найденные источники при этом покажет).

**Остальное можно оставить как есть.** В частности:

```ini
HOST=127.0.0.1
PORT=8787
DB_DRIVER=sqlite
DB_SQLITE_PATH=./data/epic-ai.sqlite
CRAWLER_ENABLED=false        # не включать — см. docs/LEGAL.md
DISCORD_ENABLED=false        # включите, когда создадите приложение в Discord
TELEGRAM_ENABLED=false
```

Сохраните и закройте notepad.

## Шаг 4. Создать первого администратора (Developer)

Роль Developer не выдаётся через интерфейс — только этой командой (ТЗ §45):

```powershell
cd backend
npm run bootstrap:developer -- --discord 581124542936907776 --name "ВашНик"
```

`--name` задаёт отображаемый ник сразу (иначе до первого OAuth-входа ник будет
«Developer»; также ник можно поменять в ⚙ → Профиль → «Никнейм»).

Ожидаемый вывод:

```
[epic-ai] Developer создан:
  • id:        1
  • username:  developer
  • identity:  discord:581124542936907776
  • роль:      Разработчик (developer)
```

Аккаунт создаётся **заранее по вашему Discord ID**. Когда вы войдёте через
Discord, система найдёт этот аккаунт и сама подтянет настоящие никнейм и аватар.

> Команда одноразовая: если Developer уже существует, она сообщит об этом и
> ничего не изменит. Принудительный повтор — с флагом `--force`.

## Вход без OAuth (для разработки)

Локальный вход без Discord-ключей — через Telegram deep-link: он не требует
ни домена, ни HTTPS, ни виджета (раздел «Telegram-вход» выше). Окно входа
сразу показывает QR и код: скан камерой → «Войти» в карточке бота → приложение
подхватывает сессию само, без кликов на компьютере.

Для скриптов и smoke-тестов остаётся API dev-входа (development + loopback;
cookie уходит вызывающему, поэтому клиенту Electron она не подходит):

```powershell
curl -X POST http://127.0.0.1:8787/api/auth/dev-login -H "Content-Type: application/json" -H "X-Epic-Client: cli" -d "{\"token\":\"<SESSION_SECRET>\",\"username\":\"developer\"}"
```

Пользователя создаёт `npm run bootstrap:developer -- --local developer`.

## CLI администратора: если в приложение не пускает

Отдельная команда работает напрямую с базой, минуя HTTP и RBAC. Нужна, когда
вход невозможен: аккаунт заблокирован, потеряна роль Developer, в базе завелись
тестовые пользователи.

```powershell
cd backend

npm run users                        # список: id, статус, роль, ник, сессии, причина блокировки
npm run doctor                       # диагностика: Developer, блокировки, документы, AI, OAuth

npm run users -- --unblock 1         # разблокировать пользователя
npm run users -- --unblock-all       # разблокировать всех
npm run users -- --developer 1       # выдать роль Developer (обходит ограничение интерфейса)
npm run users -- --role 1 admin      # назначить роль
npm run users -- --revoke-all        # завершить все сессии (сброс входов)
npm run users -- --delete 3          # удалить пользователя с identity, ролями и сессиями
```

> На драйвере `sql.js` база держится в памяти процесса, поэтому **сначала
> остановите backend** (`Ctrl+C`), затем выполняйте CLI-команды. На
> `better-sqlite3` и PostgreSQL это ограничение не действует.

Каждое действие CLI пишется в Audit Log с пометкой `via: cli`.

## Как проверить, что ИИ работает

1. **Проба провайдера одной командой** (из `backend/`):

   ```powershell
   npm run users -- --doctor
   ```

   Строка `AI-проба:` покажет либо `OK — модель …, ответ «…», N мс`,
   либо причину (нет ключа, сеть, 401/404 провайдера).

2. **В приложении:** задайте вопрос в панели. В мета-строке ответа и в окне
   источников видны модель и задержка. Если база знаний пуста, ответом будет
   честное «Нет подтверждённых данных» — это значит, что поиск и конвейер
   работают, а LLM сознательно не вызывался (ТЗ §68): наполните базу
   (админка → Knowledge Base) и задайте вопрос по документу.

3. **Голосовой ввод:** клик по микрофону → фраза появится в строке запроса
   (SiliconFlow SenseVoice тем же ключом, что и чат-модель).

## Если что-то не так

### `EADDRINUSE: address already in use 127.0.0.1:8787`

Порт занят предыдущим backend'ом:

```powershell
netstat -ano | findstr :8787
taskkill /PID <номер из вывода> /F
```

### `Уже запущен другой экземпляр backend: pid=… port=…`

Защита от двух серверов на одной базе. Остановите прежний процесс
(`taskkill /PID … /F`) или удалите `backend\data\backend.lock`, если процесс уже мёртв.

### В логе `better-sqlite3 недоступен … переключаюсь на sql.js`

Не проблема, но означает, что нативный драйвер не встал. Попробуйте:

```powershell
cd backend
npm rebuild better-sqlite3
```

Главное ограничение `sql.js`: не запускайте CLI-команды, пока работает сервер.

### Пишет «Аккаунт заблокирован»

Значит в базе у пользователя `status = 'blocked'`. Поставить его может только
администратор через `PATCH /api/users/:id/status` (право `users.block`) —
самостоятельно заблокировать себя API не даёт. Скорее всего это тестовый
пользователь, созданный прогоном `scripts/run-smoke.mjs`, под которым приложение
вошло по сохранённой cookie.

Диагностика и исправление:

```powershell
cd backend
npm run users          # кто в базе, у кого blocked и почему
npm run doctor         # полная диагностика
npm run users -- --unblock-all
```

Затем в окне блокировки нажмите **«Проверить снова»** (или «Выйти из аккаунта»,
чтобы попасть на экран входа). То же самое доступно из трея:
**Проверить аккаунт и переподключиться**.

Если в базе несколько пользователей и приложение входит не под тем — очистите
cookie-сессию Electron:

```powershell
Remove-Item -Recurse -Force "$env:APPDATA\Epic AI\Partitions"
```

и перезапустите приложение: оно снова покажет окно входа.

### Админ-панель: «Нет связи с backend: HTTP 401»

401 — это не «нет связи», а «нет сессии». Окна интерфейса грузятся с `file://`,
а Chromium не прикладывает cookie к fetch-запросам с такого origin, поэтому
renderer раньше вообще не мог авторизоваться cookie. Исправлено: main process
отдаёт токен сессии через IPC (`epic:session:token`), renderer шлёт его
заголовком `Authorization: Bearer` — backend принимает оба способа.

Само сообщение теперь честное: при 401 админка пишет «Нет активной сессии»
и предлагает кнопки **«Открыть окно входа»** и **«Повторить»**.

### Панель «дёргается» / в логе Electron `object is not iterable` (setPanelHeight)

Исправлено: `win.getBounds()` возвращает объект, а код деструктурировал его
как массив. Покрыто тестом `scripts/test-electron-windows.mjs` (геометрия
панели, раскрытие настроек вниз, окно источников справа, перенос влево у края).

### Логи backend завалены гигантскими JSON на каждый запрос

Исправлено: биндинги Fastify (`{req, res, responseTime}`) сворачиваются в резюме
вида `GET /api/health → 200 6.5 ms`, а вложенные `req`/`res` компактно
сериализуются в любых объектах. Сами строки о запросах печатаются только при
`LOG_LEVEL=debug` — консоль по умолчанию показывает события запуска,
предупреждения и ошибки, а не каждый HTTP-запрос.

### Окно входа крутится, в логах цикл `401 /api/auth/me`

Это окно Auth ждёт сессию: пока никто не вошёл, Electron опрашивает статус
(раз в 2 секунды). Чтобы войти без Discord/Telegram, используйте блок
«Локальный вход» на странице входа — нужен пользователь, созданный командой
`npm run bootstrap:developer -- --local <имя>`.

### Приложение открылось, но на вопросы отвечает «AI-сервис временно недоступен»

Не задан или неверен `AI_API_KEY`. Проверьте:

```powershell
curl http://127.0.0.1:8787/api/health
```

Поле `"ai"` должно показывать `"provider":"groq"`. Затем зайдите в
⚙ → **О программе** — строка «AI настроен» покажет причину, если ключ не принят.

### На любой вопрос «не найдено подтверждённой информации»

База знаний пуста. Загрузите фикстуры (раздел «Наполнение базы знаний» выше)
и убедитесь в ⚙ → **Правила**, что счётчик «Документов в базе» не нулевой.

### Окно входа пишет «Ни один способ входа не настроен»

`DISCORD_ENABLED` и `TELEGRAM_ENABLED` выключены. Либо настройте Discord
(раздел выше), либо используйте локальный вход.

### Кириллица в логах отображается кракозябрами

`╨╜╨╡ ╤Г╨┤╨░╨╗╨╛╤Б╤М` или `тАФ ╨░╨▓╤В╨╛╨╝╨░╤В╨╕╤З╨╡╤Б╨║╨░╤П` — это UTF-8-текст,
прочитанный консолью в другой кодировке. На работу не влияет, но читать невозможно.

Backend печатает логи через собственный логгер поверх `console.log` (не pino) —
он транскодируется Node'ом в консольную кодировку. Electron при запуске из
исходников сам переключает консоль на UTF-8 (`setupWindowsConsole()` в
`electron/main/main.js`).

Если кракозябры остались — переключите кодировку вручную **до** запуска:

```powershell
chcp 65001
$OutputEncoding = [Console]::OutputEncoding = [Text.Encoding]::UTF8
```

Либо используйте Windows Terminal вместо классического conhost — там UTF-8 по умолчанию.

### `TypeError: Converting circular structure to JSON` в логах backend

Исправлено: логгер сворачивает объект запроса Fastify в резюме `GET /api/health`
и сериализует всё остальное с защитой от циклических ссылок
(`backend/src/config/logger.ts` + тесты `backend/test/logger.test.ts`).
Если видите эту ошибку — у вас старая версия `logger.ts`, обновите файл из архива.

### `TypeError: unregisterAll is not a function` при выходе

Исправлено: `electron/main/hotkey.js` однажды собрался без строки `module.exports`
(F10 при этом не регистрировался, а выход падал). Экспорты восстановлены и
застрахованы тестом: `test-electron-config.mjs` сверяет имена, которые
деконструируют `main.js` и `ipc.js`, с фактическим `module.exports`.

### `не удалось разобрать JSON …client-config.default.json`

Все `.json` в проекте должны быть строгим JSON: комментарии `//` и `/* */` в них
недопустимы, `JSON.parse` на них падает. Проверить весь проект разом:

```powershell
node scripts/test-all.mjs     # шаг «Все .json в проекте валидны»
```

Повреждённый пользовательский конфиг не роняет приложение — берутся значения
по умолчанию, а в лог печатается путь к файлу. Пользовательский конфиг лежит в
`%APPDATA%\Epic AI\config.json`; его можно просто удалить, тогда он создастся заново.

### Electron не запускается

Проверьте, что установка прошла именно в `electron\`:

```powershell
cd electron
npx electron --version
```

Должно напечатать версию (например `v33.4.0`). Если ошибка — переустановите:

```powershell
rmdir /s /q node_modules
npm install
```
