## Расхождения и дополнения к ТЗ

Решения, которые ТЗ прямо не описывает, но которые пришлось принять:

1. **Стек backend** — Node.js 20 + TypeScript + Fastify (в ТЗ не зафиксирован).
2. **Драйвер БД** — SQLite локально вместо PostgreSQL (§63 упоминает PostgreSQL);
   слой доступа поддерживает оба, перенос — смена `DB_DRIVER`.
3. **Поиск** — собственный BM25 с русским стеммером вместо FTS5/tsvector
   (обоснование — `ARCHITECTURE.md` §2.3).
4. **Документ = тема целиком**, а не первый пост: реальные законы EpicRP разбиты
   на главы отдельными постами (Penal Code — 22 поста), а первый пост содержит
   только оглавление.
5. **Crawler выключен по умолчанию** из-за robots.txt форума (§51 требует не
   обходить технические ограничения сайта) — см. `LEGAL.md`.
6. **`/api/kb/ingest`** — ручной импорт документа через тот же Version Manager.
   В ТЗ его нет, но он закрывает легальный сценарий наполнения базы и используется
   в тестах.
7. **Клиентские настройки хранятся на сервере** (`user_settings`) с локальным кэшем
   в Electron: ТЗ этого не требует, но так настройки не теряются при переустановке
   и остаются общими для одного аккаунта.
8. **CSRF-защита** через заголовок `X-Epic-Client` для всех мутирующих запросов —
   в ТЗ не упомянута, но обязательна при cookie-авторизации.
9. **Локальный вход** `/api/auth/dev-login` — только в development, для разработки
   без публичного redirect URI. В production возвращает 404.
10. **Раунд 38.** Ключ GigaChat из кабинета — OAuth-credential (Basic), а не
    Bearer: прямой Bearer даёт 401. Провайдер gigachat сам подбирает режим:
    при 401 обменивает ключ через ngw/oauth (RqUID, scope GIGACHAT_API_PERS),
    кэширует access_token до expires_at и повторяет запрос; «id:secret»
    кодирует в base64 сам, готовый base64-ключ берёт как есть. Doctor
    подсказывает пересоздать ключ, если OAuth тоже отклонён.
11. **Раунд 37.** Бандл НУЦ Минцифры (Russian Trusted Root CA + Sub CA,
    официальные PEM по ссылке из доков Сбера) лежит в
    `backend/certs/russian_trusted_root_ca.pem` и подставлен в `AI_CA_CERT`
    по умолчанию: GigaChat работает из коробки без ручных скачиваний.
    Цепочка проверена живым TLS-хендшейком с gigachat.devices.sberbank.ru и
    ngw.devices.sberbank.ru; unit-тест следит, что в бандле оба сертификата.
11. **Раунд 36.** Полный переход на GigaChat: собственный провайдер
    `gigachat` (личный токен физлица как Bearer или OAuth ngw по
    GIGACHAT_CREDENTIALS с кэшем и обновлением токена), модели
    GigaChat-Pro/Lite/Max с цепочкой фолбэка, без response_format
    (JSON-дисциплина на промпте). TLS российских корневых УЦ: AI_CA_CERT
    (undici Agent с ca) + аварийный AI_TLS_INSECURE с предупреждением;
    подсказка в ошибке сертификата. backend/certs/README.md — откуда брать
    PEM. YandexGPT/Ollama остались альтернативами; Groq/OpenRouter/
    SiliconFlow помечены недоступными из РФ. Unit-тесты: Bearer/endpoint/
    отсутствие response_format, фолбэк модели при 404.

    дефолт переведён на YandexGPT (OpenAI-совместимый endpoint Yandex Cloud,
    стартовый грант). Их endpoint принимает модель только как
    `gpt://<folder_id>/<model>/latest` («Failed to parse model URI» на голом

    готовый `gpt://…` пропускает как есть (2 unit-теста). GigaChat и Ollama
