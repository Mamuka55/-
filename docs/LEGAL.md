# Правовые аспекты наполнения базы знаний

Этот документ описывает реальную ситуацию с `forum.epic-gta.com` и варианты действий.
Он важнее, чем может показаться: от него зависит, можно ли вообще автоматически
наполнять базу знаний Epic AI.

---

## 1. Что фактически написано в robots.txt форума

Проверено 06.10.2026, `https://forum.epic-gta.com/robots.txt` (HTTP 200):

```
User-agent: meta-externalagent
Disallow: /

Disallow: /search/
Disallow: /members/
Disallow: /whats-new/
Disallow: /online/
Disallow: /misc/
Disallow: /admin.php

User-agent: ChatGPT-User       Disallow: /
```

### Как это читать

| Факт | Значение для Epic AI |
|---|---|
| Для `User-agent: *` закрыты только `/search/`, `/members/`, `/whats-new/`, `/online/`, `/misc/`, `/admin.php`, `/api/` | Публичные разделы с правилами и законами (`/forums/…`, `/threads/…`) формально **не закрыты** для «обычных» агентов |
| Отдельным блоком перечислены **AI-краулеры** с `Disallow: /` | Владелец форума **явно и адресно запретил** автоматический доступ инструментам, которые собирают данные для AI-систем |
| Комментарий в самом файле: «AI-краулеры (обучение моделей / AI-поиск)» | Намерение владельца сформулировано однозначно, трактовать его иначе нельзя |

Epic AI — это система, которая собирает тексты форума, индексирует их и использует
для генерации ответов ИИ. По смыслу комментария владельца форума Epic AI относится
именно к той категории, которой доступ запрещён.

**Вывод:** автоматический обход форума без разрешения администрации — это нарушение
заявленных владельцем ограничений, даже если технически robots.txt «не блокирует» наш
user-agent. ТЗ §51 прямо требует: *«не должна обходить авторизацию, CAPTCHA или
технические ограничения сайта»*.

## 2. Что уже сделано в коде

1. **Crawler выключен по умолчанию.** `CRAWLER_ENABLED=false` в `.env.example`.
   При выключенном флаге `runSync()` не делает ни одного запроса к форуму,
   а `POST /api/kb/sync` возвращает `403 crawler_disabled` с указанием причины.
2. **Парсер robots.txt — часть crawler'а** (`backend/src/crawler/robots.ts`),
   а не опция «для галочки»: поддерживаются `Allow`/`Disallow`/`Crawl-delay`,
   wildcard `*` и `$`, выбор наиболее специфичной группы, приоритет длинного правила.
3. **Отдельная проверка «AI-боты запрещены».** Если robots.txt содержит группу
   AI-краулеров с `Disallow: /`, crawler пишет предупреждение в лог и в отчёт
   синхронизации, а `preflight()` возвращает `aiBotBlocked: true`.
4. **Честный User-Agent.** `CRAWLER_USER_AGENT=EpicAI-KnowledgeBot/1.0 (+контакт …)` —
   с идентификатором и способом связи, как того требует RFC 9309. Прятаться за
   браузерным UA нельзя: это и есть обход заявленного ограничения.
5. **Вежливость.** Один поток запросов, пауза `CRAWLER_DELAY_MS` (по умолчанию 2500 мс),
   учёт `Crawl-delay`, backoff на `429/503` с уважением к `Retry-After`,
   условные GET по `ETag`/`Last-Modified`, лимит `CRAWLER_MAX_PAGES_PER_RUN`,
   локальный кэш страниц. Полный прогон правил и законов — это десятки запросов,
   а не тысячи.
6. **Обходного пути нет намеренно.** В коде отсутствуют механизмы обхода CAPTCHA,
   подбора cookie, эмуляции авторизованного пользователя или ротации user-agent.

## 3. Варианты действий — от лучшего к худшему

### ✅ Вариант A. Официальный XenForo REST API (рекомендуется)

Форум работает на **XenForo 2.3** (проверено: `<html id="XF" data-xf="2.3">`).
У XenForo есть штатный REST API (`/api/` с `XF-Api-Key`) и система API-ключей,
которую выдаёт администратор форума.

- Полностью легально и предсказуемо: вы получаете структурированные данные
  (threads, posts, nodes) вместо парсинга HTML.
- Не зависит от вёрстки и темы оформления — парсер не сломается после редизайна.
- Требует от администрации форума: включить API и выпустить ключ.

**Что нужно сделать:** обратиться к администрации EpicRP с запросом API-ключа.
Код к этому готов: достаточно добавить провайдер данных `XenForoApiProvider`
рядом с существующим HTML-crawler'ом — интерфейс `ForumCrawler` и весь Version Manager
останутся без изменений.

### ✅ Вариант B. Письменное разрешение администрации + текущий crawler

Если API недоступен, но администрация проекта согласна на автоматический сбор —
получите согласие **в письменном виде** (почта/тикет, с указанием: какие разделы,
какая частота, какой user-agent, контакт для связи). После этого:

```ini
CRAWLER_ENABLED=true
CRAWLER_USER_AGENT=EpicAI-KnowledgeBot/1.0 (+https://epicrp.example/contacts)
CRAWLER_INTERVAL_MINUTES=30
CRAWLER_DELAY_MS=2500
CRAWLER_RESPECT_ROBOTS=true
```

Дополнительно попросите администрацию форума добавить в `robots.txt` исключение
для вашего бота — это снимает противоречие между разрешением и robots.txt:

```
User-agent: EpicAI-KnowledgeBot
Allow: /forums/
Allow: /threads/
Disallow: /
```

Наш парсер robots.txt корректно обработает такую группу (наиболее специфичное
совпадение по user-agent побеждает `*`).

> Проект EpicRP и форум, судя по всему, связаны: правила и законы — это внутренние
> документы игры. Если Epic AI делается по заказу/при участии администрации проекта,
> вариант B обычно решается одним сообщением во внутреннем чате. **Но формальное согласие
> всё равно нужно** — хотя бы чтобы зафиксировать разрешённые разделы и частоту.

### ✅ Вариант C. Ручной импорт и экспорт

Для старта этого часто достаточно, и это полностью легально:

- Администратор базы выгружает тексты правил/законов вручную и загружает их через
  `POST /api/kb/ingest` (право `knowledge.manage`). Эндпоинт использует **тот же**
  Version Manager, что и crawler: создаёт версию, считает word-level diff,
  переиндексирует chunks. То есть история изменений и «Обновления за сегодня»
  работают идентично.
- Подходит и для разового наполнения базы на этапе MVP v1.

Пример:

```bash
curl -X POST http://127.0.0.1:8787/api/kb/ingest \
  -H "Content-Type: application/json" -H "X-Epic-Client: cli" -H "Cookie: epic_ai_session=…" \
  -d '{
        "docType": "RULE",
        "title": "Правила сервера",
        "text": "1. Основные положения\n1.1. …",
        "url": "https://forum.epic-gta.com/threads/pravila-servera.13/",
        "threadId": 13,
        "nodeId": 38,
        "section": "Сервер / Правила сервера / Общие правила"
      }'
```

### ⚠️ Вариант D. Краулинг «как обычный посетитель» — не рекомендуется

Технически можно отправить запросы с браузерным user-agent: для `*` разделы
`/forums/` и `/threads/` не закрыты. Юридически и этически это **обход заявленного
владельцем ограничения**, потому что:

- фактически Epic AI — AI-краулер, а им доступ запрещён явно и адресно;
- маскировка user-agent'а лишает владельца форума возможности применить к нам
  его собственные правила (в том числе `Crawl-delay` и блокировку);
- это прямо противоречит ТЗ §51.

**В коде такой режим не реализован и не должен реализовываться.**
Флаг `CRAWLER_RESPECT_ROBOTS=false` существует только для тестирования парсера
на собственном стенде, а не для продакшена.

### ❌ Вариант E. Обход авторизации / CAPTCHA / rate limit

Недопустим ни при каких условиях. В коде таких механизмов нет.

## 4. Данные, которые мы уже обработали

При разработке парсер проверялся на публичных страницах форума
(главная страница, один раздел, несколько тем — порядка 15 запросов за всё время
разработки, с паузами и браузерным user-agent, без обхода ограничений).
Это была разведка структуры вёрстки XenForo 2.3, необходимая чтобы написать парсер.

Никакие полученные тексты **не сохранены в репозитории**: в качестве тестовых данных
используются вымышленные учебные документы (`scripts/fixtures.mjs`, демо-страницы).
Перед публичным релизом удалите локальный кэш crawler'а:

```bash
rm -rf backend/data/crawler-cache backend/data/*.sqlite
```

## 5. Авторские права на содержимое

Даже при наличии разрешения на crawling:

- Тексты правил и законов — это объекты авторского права владельцев проекта EpicRP.
- Epic AI **не публикует** их как собственный контент: он показывает короткие
  фрагменты с обязательной ссылкой «Открыть источник ↗» на оригинальную страницу
  форума (ТЗ §11) и датой редакции.
- Не передавайте полные тексты базы знаний внешним AI-провайдерам для обучения.
  В промпт попадают только фрагменты, необходимые для ответа на конкретный вопрос
  пользователя (`RAG_TOP_K` по умолчанию 6).
- Если используется облачный AI-провайдер — проверьте его условия: у большинства
  есть режим «не обучать модели на данных API» (у Groq/OpenAI для API-запросов
  он включён по умолчанию). Для полной изоляции используйте `AI_PROVIDER=ollama`
  и локальную модель — тогда тексты правил вообще не покидают ваш сервер.

## 6. Чек-лист перед включением синхронизации

- [ ] Получено согласие администрации `forum.epic-gta.com` (письменное, с указанием разделов и частоты)
      **или** выдан API-ключ XenForo.
- [ ] В `robots.txt` форума добавлено исключение для вашего user-agent (если согласие дано).
- [ ] `CRAWLER_USER_AGENT` содержит реальное название бота и рабочий контакт.
- [ ] `CRAWLER_RESPECT_ROBOTS=true`.
- [ ] `CRAWLER_DELAY_MS >= 2000`, `CRAWLER_CONCURRENCY=1`.
- [ ] `CRAWLER_INTERVAL_MINUTES` согласован (по ТЗ §56 — 30 минут; этого достаточно).
- [ ] Проверен `GET /api/kb/sync/logs` после первого прогона: нет ошибок и предупреждений.
- [ ] Архивные разделы (`arkhiv.*`) помечены `status='archive'` и не участвуют в поиске (ТЗ §60).
